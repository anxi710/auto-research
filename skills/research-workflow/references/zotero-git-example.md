# Example: Zotero and selected Git notes

This example comes from a user's approved reading habits.
It is an optional reference for users who want this division of work.
It is not a default for other users or projects.

## Divide the records

Zotero is the primary literature library in this example.
It holds metadata, PDFs, topic membership, reading status, and original annotations.
Maintain each metadata item there instead of editing another copy by hand.

A separate Git repository holds selected notes and comparisons across papers.
Keep a selection reason beside each selected note.
Link it through a citation key, DOI, or Zotero link.

Project records link existing library entries and notes.
They add task-specific analysis and evidence limits.
Library tags do not establish what the assistant actually read for the current task.
An optional bibliography export is an index of the primary library.

## Select this example

Select this setup in your request, project conventions, or [local preferences](preferences.md).
Record the actual library access method and selected-note location.
Resolve those locations before writing to them.

If access is unavailable, use supplied evidence and state the access limit.
Save a requested local draft when possible.
Record any library or note updates that remain unsaved.

This setup does not require migration, account setup, or a second bibliography repository.
For a standalone explanation, create only the requested output.
For a large collection, select the optional [bulk literature procedure](bulk-literature.md) when it fits the task.
