# Deliver one body of evidence in two views

Choose the requested research output and its authorized scope first.
Then choose how to present the same version to its readers.
This guide adds no permission for another stage or a dependent revision.

## Match the task's scale

A short question can finish with a concise answer, source locations, and relevant limits.
Do not create a report, ledger, or project scaffold only to satisfy a delivery format.
Use existing records and the requested destination.
For a substantial saved deliverable, provide linked researcher and agent views.
Keep them within the current stage and its human-review boundary.

| Requested output | Researcher view | Agent view |
| --- | --- | --- |
| Source study or synthesis | Explain the question, evidence, disagreements, and limits in readable prose and comparisons. | Link source identities, versions, locators, and actual reading depth. |
| Question or design | Preserve the supplied idea, alternatives, and the specific choice or protocol under review. | Link the corresponding question or plan version and decision record. |
| Run or analysis | Explain what ran, what was observed, what remains uncertain, and what the results permit. | Preserve actual execution status, raw artifacts, measurements, and fixed bindings. |
| Draft or review | Deliver the requested text or concerns with evidence and proposed responses. | Link the exact draft, claim bindings, review scope, and authoritative human decision. |

## Start with the researcher view

Make the researcher view the default reading entry.
Use Markdown as the standard format unless the user explicitly requests another format.
Keep its summary, full account, and evidence links readable at the delivery location.
Missing LaTeX sources, a PDF, compilation, or PDF layout inspection do not make a Markdown delivery incomplete.
Lead with the answer, its confidence limits, and the decision needed.
For a substantial synthesis, include a concise summary and a self-contained review.
The review should explain the question, closest work, methods, comparisons, and unresolved evidence.
Separate source reports, observed results, interpretations, and unrun proposals.
Use a readable evidence comparison when it helps distinguish competing explanations.
Include each comparison's conditions, result, source location, and limits.
Do not require the reader to inspect JSON to understand the argument.
Keep detailed hashes and operational logs in the linked technical index.

Use the optional [researcher report template](../templates/RESEARCHER-REPORT.md) when it fits the requested output.
Remove sections that the task does not need.
Keep a manuscript's required venue structure when it takes precedence.

Provide a short review entry with concrete questions:

- Which conclusion, interpretation, or next action needs the researcher's decision?
- Which exact output version is being presented?
- Which comparisons or source passages support the central claims?
- Which alternatives, missing evidence, and unrun work could change the answer?
- Which actions are already authorized, and which remain pending?

Point to the most useful sections and original source locations for those questions.
Display decision status from its authoritative record rather than maintaining another editable approval record.

## Keep the views bound to the same facts

Choose one authoritative scientific text and its existing evidence records.
Derive summaries and rendered views from that fixed version.
Reuse claim and source IDs when they exist.
Map readable sections and comparisons to those IDs and evidence versions.
Preserve uncertainty, negative results, reading limits, and actual execution status in both views.
Do not introduce a stronger claim in a summary or presentation.

The agent view is an evidence and continuation index, not a second scientific narrative.
Reuse the current task, result, source catalog, ledger, state, and decision records as applicable.
Do not require all these records when the task does not use them.
Follow the existing [collaboration format](collaboration.md) for fixed artifacts and results.
Keep human decisions in their existing authoritative location.
Do not add competing approval fields to a ledger or summary.

Record the exact revisions or SHA256 digests for the presented files.
When preparing a new result, list each submitted view and editable source in its artifacts.
Keep an already sealed result and its artifacts unchanged.
Save a new attempt or separate delivery record that links the original when adding later views.
An [evidence ledger](evidence-ledger.md) binds claims to its specified UTF-8 manuscript and source snapshots.
It does not validate a PDF, translation, paraphrase, or its scientific equivalence automatically.
Bind those files separately and inspect their agreement with the authoritative claims.
If a fact or evidence version changes, preserve the old views and identify which new views need review.

## Optional rendered formats

Use LaTeX or PDF only when the user explicitly requests that format.
A formal report does not select LaTeX automatically.
For Markdown delivery, do not generate LaTeX or PDF files, install TeX, or require compilation or PDF layout inspection.
If the user selects a rendered format, provide its editable sources and relevant build instructions alongside the readable output.
For LaTeX, include the bibliography and figure sources that the report uses.
Record missing dependencies or an unrun build without claiming successful compilation.
Do not install missing tools without explicit user authorization.
For a compiled report, inspect page layout, citations, references, and reading links.
Keep a usable text or source entry when a PDF link cannot reach the evidence.
Compiling and checking layout do not establish scientific support or human approval.
Selecting a rendered format for one output does not change the Markdown default.
If the user requests Markdown again, return to that format without requiring a rendered copy.

## Preserve the review boundary

Follow [human review](human-review.md) for each research output and its exact version.
The [S7 rule](workflow.md#s7-review-discuss-and-respond) also applies before using AI critique for dependent revisions.
Choosing two views or a document format is not scientific approval or a review waiver.
Preparing a joint delivery package does not bypass intermediate review.
A standalone answer can end without approval only when no dependent work follows.
Keep execution completion, AI assessment, and the researcher's decision separate.
