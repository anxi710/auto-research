## Evaluation and decision

The [test protocol](../tests/evolution.md) defines the tasks and acceptance conditions.
We wrote those cases after the initial procedure draft and before the independent executions.
This bootstrap change does not claim a prospectively measured improvement.

The paired task used the same synthetic files and request.
Each session had at most 15 local tool calls.
Network access, experiments, and nested agents were outside the test scope.

| Case | Baseline | Candidate | Decision basis |
| --- | --- | --- | --- |
| Scope, old layout, and unknown job | Passed. | Passed. | Both preserved the required behavior. |
| Mixed evaluation results | Supplied synthetic outputs only. | Rejected the failing candidate. | A lower tool count did not override a required condition. |
| Temporary recovery | Saved Git baseline. | Reversed the procedure diff. | Earlier procedure returned without losing unrelated records. |
| Overlapping recovery | Saved Git baseline. | Refused automatic application. | Later edits remained intact. |

The [results](../tests/RESULTS.md) record the observations and limits.
The evidence file preserves both runs and the independent evaluation.
Tool counts were reported by the test assistants, not measured by separate telemetry.

Decision: adopt the requested workflow capability within this repository.
The paired case was tied, so it supports no claim of improved research performance.
No further candidate or improvement round was started.
