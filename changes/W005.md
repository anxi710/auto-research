# W005: Add an optional bulk literature workflow

Status: adopted.
Date: 2026-10-23.
Baseline: `ea6979a`, package version `0.1.0`.
Candidate: the unreleased package version `0.1.1`, alongside [W004](W004.md).

## Request and scope

The user requested a reusable example of their large-collection reading pattern.
It connects Zotero, zpm exports, rclone uploads, Google Drive, and NotebookLM analysis.
The user also requested a toolkit that each researcher can customize.
This change adds an optional procedure inside the portable skill.
It does not make these tools a shared default.

Allowed files cover routing, the new procedure and template, source notes, documentation, and focused evaluation records.
No collection, remote folder, notebook, or live analysis task was selected.
This change does not run an export, upload documents, or alter accounts.
It does not activate the pending lessons L2 to L4 from W002.

## Fixed evaluation

The [bulk literature tests](../tests/bulk-literature.md) were written before the new procedure.
Use one candidate and a paired baseline comparison in temporary directories.
Use fresh sessions with identical inputs, local tools, and a 15-call limit.
Protect source identity, reading depth, existing records, and task scope.
Stop after the focused exercise and package inspection.

The requested capability is a traceable handoff across the chosen tools.
Its records must distinguish file transfer, source import, evidence extraction, and original-source review.
NotebookLM outputs alone cannot establish complete coverage or scientific conclusions.

## Evidence and decision

Evaluation: both baseline and candidate preserved the required evidence and incomplete-coverage conditions.
Each reported five local tool calls.
The candidate saved the new corpus record with separate transfer, import, extraction, and reading counts.
The [evidence file](../tests/evidence/W005.json) preserves inputs, outputs, hashes, reports, and independent review.
Package metadata, local links, and plain-English inspection passed.
Decision: adopt the requested optional procedure in package version `0.1.1`.

The final route explicitly includes project conventions after review identified an omission.
That clarification received inspection rather than another behavioral run.
The paired exercise does not show an advantage in task success or tool count.
Real export and import behavior remains untested.
Do not claim faster analysis or better research from these synthetic cases.

For recovery, reverse this change's procedure and routing while preserving later edits and all research records.
If the active package behavior changes, assign a new version.
Keep the change record and evaluation evidence after recovery.
