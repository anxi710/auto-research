## Decimal correction after parent review

The parent reviewer reproduced four numeric binding failures in the first delivered candidate.
Binary float parsing erased nonzero tiny values and rounded distinct decimals to equal values.
It also rounded `9007199254740993.0` before comparing that value with an exact integer.
These failures affected method values, baseline values, and nested conditions.
The earlier passing cases did not cover these distinctions.

The correction parses fractional and exponent tokens with the standard-library `Decimal` type.
Equality uses exact decimal and integer values without arithmetic or rounding.
The earlier finite binary64 conversion check remains only as an input-range rule.
Its rounded float never supplies a value for comparison.
The format still treats `1` and `1.0` as equal and booleans as distinct from numbers.
Unsupported extreme exponents fail with a schema diagnostic instead of a traceback.
The legacy task, result, and review parser stays unchanged.
