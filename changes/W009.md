Status: adopted.
Baseline package: `0.1.4`, including the uncommitted W008 changes.
Adopted package: `0.1.5`.
Date: 2026-10-23.

The user approved N1 through N3 after the N7 repair.
The scope covers an optional entry, one collaboration procedure, and the minimum record templates.
It also covers related test cases, version badges, and evidence records.
This round permits one candidate and local synthetic exercises within 60 minutes.
It excludes a record checker, CI changes, runtime adapters, live services, and publication.

## Fixed acceptance conditions

Delegated assignments must identify their owner, input version, output scope, acceptance evidence, approved budget, and stop condition.
The coordinator must keep shared state as navigation to those assignments.
Review must distinguish execution from acceptance and retain negative results.
Old revisions and withdrawn acceptance must not support current conclusions.
Submitted files and old project paths must remain unchanged.
Unknown remote jobs must retain their identity and block replacement until their status is known.
A standalone abstract task must create only its requested answer and retain its reading limit.

The three paired cases cover assignment, review after interruption, and standalone reading.
A separate candidate case covers a withdrawn upstream review with an unchanged artifact hash.
Each execution receives the same local tool access, ten-call limit, and five-minute limit.
The execution contexts do not receive the expected results or other runs' outputs.
An independent evaluator receives the fixed criteria and output files without a preferred conclusion.

## Candidate scope

The entry links to one [collaboration procedure](../skills/research-workflow/references/collaboration.md).
Task and result templates bind submissions to saved contracts and exact file versions.
The existing review template gains an optional acceptance block with one decision owner.
The handoff template stays outside sealed attempts.
The state template links to these records without copying their acceptance fields.
Existing claim states, stages, job records, and the evolution procedure remain unchanged.

The design review added explicit input hashing and rules for reused results under a changed contract.
It also clarified who writes acceptance and how later reviews replace earlier decisions.
All candidate exercises use the same final package bytes.

## Decision and recovery

Adopt the optional record format within the user's approved scope.
The independent evaluator found 40 passing criteria, no failures, and 11 uncertain criteria across seven executions.
All 40 protected-file comparisons passed, and all supplied skill files remained unchanged during the exercises.
Both versions met the requirements that the saved files can establish.
The separate case correctly withheld downstream acceptance after an upstream withdrawal.
The uncertain criteria concern prohibited actions that file snapshots cannot rule out.
Tool-call counts and the absence of external actions come from execution reports, not an independent action trace.
These limits do not establish runtime enforcement or a measured research benefit.
The dispatch output count increased from three files to seven.
Keep the records optional when a task does not need them.
The [evidence record](../tests/evidence/W009.json) preserves inputs, outputs, evaluation results, and the exact patch.
Use that patch to reverse this change without undoing W008 or later work.
Keep research records and this decision history during rollback.
Assign a new package version if rollback changes active behavior.
Do not upgrade copied or globally installed packages in this round.
Observe the records during the next real delegated research task.
