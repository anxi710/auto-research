## Finding and authority

The user identified loss of earlier correct content as a key workflow risk.
The user also requested a separate record of the observed defect and its limits.
This round adds development regressions within the existing revision workflow.
It does not change the architecture holdout, default human-review boundary, or project scope.
The three writing skills identified in [W022](W022.md#writing-skills) guide this document and its scope review.

Two findings need separate interpretation.
The first development rubric missed deleted useful content inside a changed report.
Its earlier pass, reconstructed snapshot, corrected criteria, and reruns remain in the [W022 history](../tests/revision-history/correction.json).
That record does not show a native agent forgetting content.

The later W022 checker also accepts valid selected evidence fields beside an unsupported new sentence.
The existing adversarial test demonstrates this limit at commit `fe52cbf`.
Its mechanical completion does not grant scientific acceptance.
The report already requires independent content assessment.
Treating that mechanical result as complete scientific review creates the workflow risk.

The actual W022 native actor corrected both supplied cases without an observed retention failure in the independent review.
The negative cases in this follow-up are authored counterexamples, not recorded model-generated failures.
They test what the checker and review process can detect.

## Interpretation and limits

The checker binds selected claims and evidence.
It does not find every assertion or understand whether arbitrary prose follows from the evidence.
A later correct addition can coexist with an older unsupported claim or a deleted limitation.
That local checking scope explains the reproduced mechanical miss.
It does not establish a general model mechanism or a frequency of revision loss.

[Mr Dre v1, Section 4.2 and Appendix B.4](https://arxiv.org/html/2601.13217v1) already separates feedback incorporation from damage to earlier content.
This record contributes a reproducible toolkit case and a specific process correction.
It makes no claim of scientific novelty.
No test here can guarantee that arbitrary future revisions preserve all correct meaning.

## Correction and observed results

The helper now saves retained items and the affected closure before writing the new artifacts.
It accepts explicitly declared equivalent wording for selected retained statements.
It also flags listed withdrawn text when that text returns to a selected output.
The withdrawal rule includes fixed evidence and a reason, rather than requiring all old text to survive.
Existing human decisions and scientific assessments retain their original authority.

The [patched comparison](../evaluations/revision-retention/patched-results.json) uses the identical first result, second-round input, candidate, and rubric.
The same restored assertion now produces exit code 1 and status `blocked`.
The newest requested comparison still passes, which separates implementation from regression detection.
The full candidate advances the task from revision 2 to revision 3 and retains the earlier result unchanged.

## Reproduce the mechanical miss

Use a temporary copy so that the saved comparison remains unchanged:

```sh
retention_dir=$(mktemp -d)
cp -R evaluations/revision-retention/baseline-fixture/. "$retention_dir/"
PYTHONPATH="$PWD/skills/research-workflow/scripts" python3 -B \
  evaluations/revision-retention/baseline-revision_loop.py \
  --root "$retention_dir" --case round2-bound-case.json \
  --candidate round2/reintroduced-ranking.json --output runs/baseline-replay
python3 -B skills/research-workflow/scripts/revision_loop.py \
  --root "$retention_dir" --case round2-bound-case.json \
  --candidate round2/reintroduced-ranking.json --output runs/patched-replay
```

The baseline returns 0 and the patched command returns 1 for this fixed regression.
Neither exit code establishes scientific correctness for arbitrary prose.
Run `python3 -B -m unittest discover -s tests -p 'test_revision_retention.py'` for the bounded regression set.
