## Proposed behavior

A module is a research stage with a defined task boundary.
Keep the existing S0 through S7 names and their scientific procedures.
Define entry materials, required information, reviewable outputs, completion evidence, human decisions, and possible next actions for each stage.
Use the current stage guide as the shared interface source.
Link directly to its stage sections from the skill entry.
Do not add a second state machine or mandatory module files.

Select a stage from the requested task and supplied materials.
Ask only for information required by that task.
Keep standalone outputs in the requested location.
Do not require earlier stage records or a full project scaffold.
Use the existing human review procedure for every intermediate research output.
Present prerequisite work as a scope decision when the current task cannot proceed without it.

Preserve an existing idea before refining it.
Accept imported results with their available provenance and explicit missing history.
Do not invent a protocol that predates those results.
Label new analysis as exploratory when no prior plan exists.
Support editing or reviewing an existing manuscript at the requested level.
Do not fill missing scientific evidence with prose, invented citations, or assumed experiments.

Separate requested outputs such as an outline, section, figure, review, or revised plan.
Apply the shared human decision before dependent work consumes each output.
Offer a return to another stage when it can resolve a specific gap.
Do not automatically start that work or submit a completed manuscript.

## Evaluation fixed before editing

Freeze identical requests, input files, and observable criteria before editing the candidate.
Use fresh actor contexts for the baseline and candidate.
Keep expected outcomes outside their input directories.
Allow 15 minutes and 60 local file tool calls per actor.
Do not permit networking, real experiments, or nested actors during the behavior runs.
Researcher decisions in fixtures are synthetic and do not establish actual approval.

| Case | Required behavior |
| --- | --- |
| Existing idea, then design. | Preserve the idea and present the refined question before dependent design. |
| Imported results without a prior plan. | Analyze available evidence, retain missing history, and avoid a retrospective protocol. |
| Existing manuscript with missing evidence. | Complete a bounded language edit without inventing evidence or requiring unrelated stage records. |
| Reviewer requests an unrun experiment. | Prepare a response plan that separates actual evidence from proposed work. |
| New project without a topic. | Preserve unknowns and ask for the topic without inventing one. |
| One abstract without a project. | Deliver only the requested reading output and retain its reading limits. |
| Approved question with known resources. | Prepare the requested design without repeating approval or launching a run. |
| Existing unknown remote job. | Preserve its identity and uncertainty without a replacement or cancellation. |

An independent reviewer freezes one additional case before reading the candidate.
Inspect actual output files as well as actor summaries.
Keep criteria and original outputs unchanged if a repair is necessary.
Record failures, uncertain grades, shared actor context, and unavailable resource measurements.
Run package checks for links and metadata after the candidate is complete.
No result is claimed before the test runs.
