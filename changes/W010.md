# W010: Inspect selected collaboration records

Status: adopted.
Baseline package: `0.1.5`, including the uncommitted W008 and W009 changes.
Adopted package: `0.1.6`.
Date: 2026-10-23.

The user approved N4 after reviewing its concrete scope.
This round adds a read-only local command, related documentation, and offline tests.
It allows one candidate within 90 minutes.
It excludes CI, automatic repairs, record migration, runtime adapters, live services, and publication.
The baseline snapshot preserves the existing uncommitted work.

## Fixed acceptance conditions

The command must inspect selected collaboration records and their required references.
It must retain custom record layouts and ordinary discussion reviews.
It must report invalid fields, unsafe paths, missing files, and changed file hashes with stable diagnostic codes.
Results must match their fixed contracts and identify their current contracts.
Historical results must remain unchanged when current contracts differ.
Required dependencies must retain valid acceptance under the supplied review history.
A later review must invalidate a dependency that still pins the replaced acceptance.
This rule also applies when the artifact bytes stay unchanged.
Cycles and conflicting identities must produce diagnostics without an endless traversal.
The command must preserve research file bytes and inventories.
A clean report must not claim scientific truth, complete review history, or actual external job status.

## Comparison

The baseline has no record checker.
That is an unavailable capability, not a measured research-quality failure.
The paired command cases use a valid custom layout and a withdrawn upstream acceptance.
The same commands run on separate copies of the fixed synthetic files.
The existing offline suite runs with the same Python in both package copies.
An independent case tests a replacement that accepts the same result but invalidates the old dependency pin.
The implementation and test authors work in separate contexts from fixed requirements.
An independent reviewer inspects the implementation and separate case.

The baseline passed its 23 existing offline tests with Python 3.14.8 on Linux.
The candidate passed all 61 tests in 6.562 seconds, including 38 checker tests.
The first 36 checker tests were written before their author saw the implementation.
Review findings added two regression tests and assertions about diagnostic paths.
Both fixed command cases produced the expected candidate outcomes without changing research files.
The baseline had no checker, so its commands returned a missing-script error.

The independent case passed all three states.
The original acceptance passed before replacement.
The old dependency pin failed after another review accepted the same result.
A new downstream revision with the new pin passed while retaining the old artifact.
All record bytes and inventories remained unchanged.

Review found a numeric overflow that escaped the first JSON parser.
The final parser rejects both non-finite constants and exponent overflow.
Review also found that rejected CLI arguments produced unsafe diagnostic paths.
The final command labels these selection errors with `.` and retains the rejected argument in the message.
Both findings have saved reproductions and passing follow-up checks.

The [test results](../tests/RESULTS.md) record the commands, environment, outcomes, and limits.
The [evidence record](../tests/evidence/W010.json) preserves fixtures, outputs, review findings, hashes, and the exact implementation patch.

## Decision and recovery

Decision: Adopt the optional checker because the requested local checks and relevant protections passed.
The [active procedure](../skills/research-workflow/references/collaboration.md#inspect-saved-records) remains optional.
The command does not upgrade old projects or installed skill copies.
Use the saved implementation patch and before-and-after hashes when reversing this change.
Reverse only that patch if the checker causes a regression.
Preserve W008, W009, all research records, and this decision history during rollback.
Assign a new package version if rollback changes active behavior.
Observe diagnostic accuracy during the next real task that uses collaboration records.

The tests do not establish complete review history, actual decision authority, scientific truth, or live job state.
The checker requires idle writers because its reads do not form a locked snapshot.
Python 3.9 syntax passed inspection, but only Python 3.14.8 ran the tests.
Other operating systems and real research projects remain untested.
