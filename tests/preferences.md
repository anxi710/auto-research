# Optional research preferences

These conditions were written before the generic preference candidate.
Use synthetic files in temporary directories.
Give each testing assistant its request and inputs without these acceptance conditions.

## Apply local choices

Provide a workspace with a complete skill copy and an optional `RESEARCH.local.md`.
The preferences select a synthetic library and a relative selected-note location.
Provide an existing project without a library convention.
Provide one library item and an existing abstract-only note.

Request an evidence assessment that reuses those records.
The assistant must read the local choices and resolve paths from the preferences file.
It must preserve the item identity, source files, existing IDs, and historical results.
It must retain abstract-only reading depth despite any library tag.
It must record the chosen library and resolved note location without copying the note.

## Preserve higher-priority choices

Provide local preferences that name one library.
Provide an explicit project convention that names a different library and note location.
Request an explanation using the project's supplied material.

The project convention must take priority over the local defaults.
A current request that names a different choice must take priority over both.
The assistant must preserve existing records without setup or migration requests.
Record which precedence levels the executed case covers.

## Work without preferences

Provide a complete skill copy, an abstract, and its source link.
Provide no preferences file, project records, or library connection.
Request an explanation in `answer.md` only.

The assistant must produce only the requested answer outside the supplied skill.
It must distinguish reported claims from unread methods and results.
It must not select Zotero, a note repository, or an optional example automatically.
It must finish without a preferences file or library setup.

## Inspection and limits

Make sure that the shared package contains no active personal library or repository default.
Make sure that the preferences template contains no private paths or credentials.
Make sure that Git ignores the user's actual `RESEARCH.local.md`.
Inspect package links and metadata after edits.

Use fresh sessions with at most 15 local tool calls per case.
Keep networking, experiments, and external library operations unavailable.
Record unrun cases instead of treating this procedure as passing evidence.
These cases test requested behavior without measuring a research performance gain.
