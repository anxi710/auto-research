## Fixed comparison

| Case ID | Input values | Purpose |
| --- | --- | --- |
| control | `[1.0, 2.0, 3.0]` | Include an exactly representable control and retain ties. |
| cancellation | `[1e16, 1.0, -1e16]` | Examine an ordering effect with unequal magnitudes. |

Evaluate all six permutations of each three-value case in `itertools.permutations` order.
Number each case's orderings from 1 through 6.
The result has 12 ordering rows and 24 method outputs.
Use identical binary inputs for both methods in each ordering.
There is no random sampling, training, or parameter search.

The `naive` method starts from `0.0` and adds each float with an explicit loop.
It does not use the built-in `sum` implementation as a floating-point baseline.
The `fsum` method uses `math.fsum` on the same sequence.
The reference is the rational sum of each actual input converted with `Fraction.from_float`.
The reference describes binary inputs, not idealized decimal strings.

Compute absolute error as `abs(Fraction.from_float(output) - reference)`.
Store reference and error as integer numerator and denominator pairs.
Store inputs and outputs with `float.hex` to retain their exact float identities.
Reject invalid input, nonfinite values, and nonfinite method results.
Report all ties, errors, failed attempts, and evidence against the hypothesis.
Do not require a favorable result for `fsum`.
